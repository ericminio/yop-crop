# Project guidance

Do not add comments to any code in this project, including tests and configuration files.
Use clear names and structure to express intent. Put explanations in documentation when needed.

Before implementing a fix or behavior change, write and run the relevant test against the existing code. Confirm it fails for the intended behavioral reason, not a setup, syntax, or unrelated error. Only then implement the change and rerun the test to confirm it passes. Do not substitute a manual reproduction or a retrospective red run for this sequence.
